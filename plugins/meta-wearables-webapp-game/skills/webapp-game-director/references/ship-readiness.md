# The reasoned case for more iteration

Reference for the `webapp-game-director` skill — read when the user signals they want to ship.

When the user says "is it ready?", "I think it's done", or "let's release" — **do not hard-block,
and do not rubber-stamp.** Make the honest case and then defer to them.

Present a short ship-readiness picture:

- **Rubric gaps** — which dimensions are still weak, with the specific evidence.
- **Open playtest signals** — questions the playtests haven't answered yet, or problems observed
  but not yet fixed.
- **The trade** — concretely, what iterating a bit more would likely buy (and roughly what it
  costs), versus the real cost/risk of shipping as-is. Include the case *for* shipping when it's
  legitimately strong (momentum, a deadline, "good enough to learn from real users").

Then say your recommendation plainly and **let the user decide.** The goal is a well-reasoned
argument for why more iteration would be wise — not a gate they have to defeat.
